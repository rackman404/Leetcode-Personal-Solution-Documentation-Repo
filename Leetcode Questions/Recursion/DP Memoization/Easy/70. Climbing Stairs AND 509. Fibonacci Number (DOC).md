[70. Climbing Stairs](https://leetcode.com/problems/climbing-stairs/)

You are climbing a staircase. It takes `n` steps to reach the top.

Each time you can either climb `1` or `2` steps. In how many distinct ways can you climb to the top?

**Example 1:**

**Input:** n = 2
**Output:** 2
**Explanation:** There are two ways to climb to the top.
1. 1 step + 1 step
2. 2 steps

**Example 2:**

**Input:** n = 3
**Output:** 3
**Explanation:** There are three ways to climb to the top.
1. 1 step + 1 step + 1 step
2. 1 step + 2 steps
3. 2 steps + 1 step

**Constraints:**

- `1 <= n <= 45`

---
# Input/Output

Input:
- number from 1 to 45 
	- Given the small constraint, its somewhat clear that there's gonna be a lot of recursive calls that have to be done very quickly (thus allowiing memoization for optimization)


Output:
- The number of steps needed to get from n = 1 to n = input n


---
# Implementation/Approach


## Subproblems
- We note that the total number of steps can be equal to the combination of total number of steps - 1 + total number of steps - 2 ... 0.
- We can therefore use recursion to continually sum all possible step combinations for a given N value.
- We can use a top down approach for this (start the recursive tree at N)

### Base Case
- We note that the base case should be when we reach bottom of stairs (i.e n = 1), at this point we simply return 1

## Branches
- If n - 2 > 0:
	- We can do recursive(n-1) and recursive(n-2) (to indicate stepping either 2 or 1 steps down)
- else:
	- we can only do recursive(n-1), only option possible as we'd go past the bottom of staircase

## Memoization
We can modify a brute force approach to this question via the use of a external table (i.e external to each call). Most recursive calls will be repetitive and so the table can be used to return steps taken up to table\[n] point which should drastically cut down on recursive calls (only time we'd have to continue a given branch down to a given n value is if it hasn't been cached yet, **otherwise we waste time solving the same exact subproblem everytime**)

#uses memoization to reduce recursive calls needed to save on time (TLE otherwises)
class Solution:
    def climbStairs(self, n: int) -> int:
        self.table = [-1] * n
        #print (self.table)
        return self.climbStairInstance(n-1)

    def climbStairInstance(self, n: int) -> int:
        #print (n)
        if (n == 0): #base case, N = 1, reached bottom 
            return 1 
        elif (self.table[n] == -1): #if recursive call not already cached
            if (n - 2 > 0): # if we can actually go down 2 steps
                self.table[n] = self.climbStairInstance(n-1) + self.climbStairInstance(n-2) # the branch options
                return self.table[n]
            else:
                #print ("one step: " + str(n))
                self.table[n] = self.climbStairInstance(n-1) + 1
                return self.table[n]
        else: #IMPORTANT: we can just straight up get the accumulated combination at that N value, saving on recursive calls
            return self.table[n]
