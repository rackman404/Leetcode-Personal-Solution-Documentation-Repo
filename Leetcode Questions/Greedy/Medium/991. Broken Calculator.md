
[991. Broken Calculator](https://leetcode.com/problems/broken-calculator/)

There is a broken calculator that has the integer `startValue` on its display initially. In one operation, you can:

- multiply the number on display by `2`, or
- subtract `1` from the number on display.

Given two integers `startValue` and `target`, return _the minimum number of operations needed to display_ `target` _on the calculator_.

**Example 1:**

**Input:** startValue = 2, target = 3
**Output:** 2
**Explanation:** Use double operation and then decrement operation {2 -> 4 -> 3}.

**Example 2:**

**Input:** startValue = 5, target = 8
**Output:** 2
**Explanation:** Use decrement and then double {5 -> 4 -> 8}.

**Example 3:**

**Input:** startValue = 3, target = 10
**Output:** 3
**Explanation:** Use double, decrement and double {3 -> 6 -> 5 -> 10}.

**Constraints:**

- `1 <= startValue, target <= 109`

---
## Input/Output

Input:
- StartValue, can be lower or higher than target
- Target, the number to reach

Output:
- Number of multiplication or subtraction steps needed to get to Target from StartValue

## Solution
```python
#import math

#simplifies previous approach even more
class Solution:
    def brokenCalc(self, startValue: int, target: int) -> int:
        operations = 0

        #special case
        if (startValue > target): #can just subtract to find operations (since -1 is the only one possible)
            return startValue-target
        if (startValue == target):
            return 0

        #perform preprocessing, figure out the target number at each step (only real way of doing it greedy i think)
        while (target > startValue):
            if (target % 2 == 1): #if odd
                target += 1
            else:
                target /= 2
            operations += 1
                
        return int(operations + startValue - target)
```

# Naive Approach and Solution

Before figuring out the optimal solution, I had used a solution as shown below.

Inefficient because we are effectively attempting to recreate the target -> startValue approach using a stack to trace our way to the intended target, multiplying or subtracting on our way to the next divided target until we reach the actual target. Bad solution as we can just implicitly get the multiplications/subtracts by only dividing or adding as shown above.

``` python
import math

#this question took way too long to figure out by hand ngl
#two steps:
# preprocess by figuring out the best possible option at each passthrough substep (find the repeated divided targets)
# passthrough and -1 if smaller than current divided target, * 2 if bigger, pop if at target
# - repeat until found actual target
class Solution:
    def brokenCalc(self, startValue: int, target: int) -> int:
        operations = 0

        #perform preprocessing, figure out the target number at each step (only real way of doing it greedy i think)
        divideStack = [target] #using stack to retrace the steps later
        while (divideStack[-1] > startValue):
            #honestly just rounding up based on the fact that it just works when i worked it out on paper 
            divideStack.append(math.ceil(divideStack[-1]/2)) 
        
        currValue = startValue
        #single passthrough (kinda)
        while (True):
            if (currValue == divideStack[-1]): #can move on to the next repeated division result
                divideStack.pop()
            elif (currValue > divideStack[-1]): #keep stepping towards next repeated division target
                currValue -= 1
                operations += 1
                pass
            elif (currValue < divideStack[-1]): #keep stepping towards next repeated division target
                currValue *= 2
                operations += 1
                pass
            if (currValue == target): #at target
                return operations
            #print (currValue)
        
```
