
[881. Boats to Save People](https://leetcode.com/problems/boats-to-save-people/)

You are given an array `people` where `people[i]` is the weight of the `ith` person, and an **infinite number of boats** where each boat can carry a maximum weight of `limit`. Each boat carries at most two people at the same time, provided the sum of the weight of those people is at most `limit`.

Return _the minimum number of boats to carry every given person_.

**Example 1:**

**Input:** people = [1,2], limit = 3
**Output:** 1
**Explanation:** 1 boat (1, 2)

**Example 2:**

**Input:** people = [3,2,2,1], limit = 3
**Output:** 3
**Explanation:** 3 boats (1, 2), (2) and (3)

**Example 3:**

**Input:** people = [3,5,3,4], limit = 5
**Output:** 4
**Explanation:** 4 boats (3), (3), (4), (5)

**Constraints:**

- `1 <= people.length <= 5 * 104`
- `1 <= people[i] <= limit <= 3 * 104`

# Input/Output
Input:
- arbitrary list of people weights
	- Length of 1 to alot
	- weight of each person is always lower than the max limit

Output:
- number of minimal amt boats

# Implementation/Approach

The point of this question is to reduce number of boats used. We also note that no matter what we can always transport a person across regardless of weight.

Thus, we can solve the question by just figuring out how if we can pair up the heaviest person with the lightest person. 
2 Cases:
- The weight exceeds boat, since not even the lightest person fits in with them, we can only ever let the heavy person go alone on the boat. We then evaluate the same lightest person with next heaviest person.
- The weight does not exceed boat, we can transport both and move on to the next pair.
In either case, we can always just continue moving at least one pointer forward. This should ensure that solution is O(N) in the worst case

We can take a greedy approach by doing a traditional sort (no order matters here), then having a pointer on the heavy and pointer on the light end. The single passthrough will then evaluate the two cases outlined above until the pointers are past each other, at which case we return the number of boats used, which should be the absolute minimum number of boats needed.

# Solution

```python
#kinda important assumption i realized at each step of the question (i.e after moving ptr) we will increment minBoat 1, the bulk of the question is about wheather or not we can minimize boats (i.e move front/back ptrs) at once rather than only one at a time

class Solution:
    def numRescueBoats(self, people: List[int], limit: int) -> int:
        minBoat = 0
        people.sort()

        startPtr = 0
        endPtr = len(people) - 1

        while (endPtr - startPtr > 0):
            if (people[endPtr] + people[startPtr] <= limit):
                startPtr += 1
                endPtr -= 1
            elif (people[endPtr] <= limit):
                endPtr -= 1
            else: #implicitly, startptr is the one fitting the limit, and can thus be put on boat
                startPtr += 1
            minBoat += 1

        #edgecase (startPtr == endPtr)
        if (startPtr == endPtr):
            minBoat += 1 #should always be possible to transport last person since question assumes theres always a possible answer
            
        return minBoat
```
